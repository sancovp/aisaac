The seven crafts

Seven component types, seven masters.

The component ladder, smallest to largest. This is the actual set of things Claude Code software is built out of — the engineer builds any of them itself, or hands the work to the master who owns that craft.

skill

Skillwright

A packaged capability — a lean instruction file plus the resources an agent equips along with it.

mcp

Toolwright

A tool server — real executable tools an agent can call, with typed inputs and outputs.

prompt

Promptwright

A prompt or persona — the thing that puts a model into a role and holds it there.

harness

Harnesswright

A harness — sequenced typed outputs across a turn, ordered on a dependency graph.

team

Teamwright

A team of subagents coordinating against a shared task list.

workflow

Flowwright

A deterministic script that fans work out to subagents in phases.

system

Systemwright

A whole operating system — a directory plus a core loop that makes an agent govern itself.

The part that is unusual

An app that knows how it was built.

It is built over a documentation-and-development system that every agent inside it carries. So it can inspect its own structure and explain, as a living example, exactly how an app like it is made. The thing that builds components is itself a component you can open and read.

This is the one claim on the page you can falsify in about a minute: install it, ask it how it was built, and check the answer against the directories on your own disk. If the answer were written in rather than read out, that check would fail — which is the point of naming the test here rather than hoping you skip it.

Straight terms

What you’re buying, honestly.

Nothing — which makes this the easy one to be straight about. The trade is your time, not your money. It ships as a container and it needs a provider key, so you have to be comfortable running one and setting an environment variable. If you are not, that is fine; this rung is simply not the one for you yet, and rung 4 exists precisely because not everyone wants to be the person running it.

What it can’t do yet. It inspects and extends itself, and it compiles components well. It does not yet compile other whole systems from scratch — the self-inspection is real, the fully general compiler is not there. It also assumes Claude Code specifically: this is not a provider-agnostic build tool and it is not trying to become one.

The specialists are narrow on purpose. Each one is good at its own craft and only its own craft. Work that spans several of them still goes better when you know roughly what you want. It is an engineering department, not a wish granter, and the difference shows up on the ambiguous jobs rather than the clear ones.
